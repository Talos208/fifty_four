# 「試す」パネルのモデル一覧の自動更新 設計

日付: 2026-10-17

## 意図と背景

shinasadame の「試す」パネルで、新しいモデルを選びたいのに選択肢に出てこない。選択肢は
`shinasadame/k8s/base/deployment.yaml` の環境変数 `SHINASADAME_MODELS` に固定の文字列
(`google/gemini-3.8-flash-latest,anthropic/claude-sonnet-5-5,xai/grok-4.7`)で書かれており、
新しいモデルが出るたびに手で書き換える必要がある。

各社の「使えるモデル」を自動で取得して一覧を保つ。選択肢が数百件になるので、画面は複数段のメニューにする。

## ゴール

- 各社(Google / Anthropic / OpenAI / xAI)の、取得時点で使えるモデルを、新しいものから古いものまで全部取得し、
  選択肢にする。**その会社の API キーを持っているかどうかは問わない。**
- 取得結果はリポジトリにコミットするファイルにする(モデルの増減を差分でレビューできる)。
- スクリプトは `skaffold run` のビルド前に自動で回る。コミットは自動ではしない(差分を見てから人が行う)。
- 「試す」パネルのモデル欄を、会社 ▸ 系列 ▸ モデルと横に開く複数段のメニューにする。

## ノンゴール

- キーを持っている会社だけに絞る、といった絞り込み。
- 価格・コンテキスト長・能力の表示。
- 画面を開くたび、実行時にリアルタイムで取得すること(一覧はビルド時に固定される)。
- LM Studio(ローカル)のモデル一覧の取得。
- `acceptance.html` のモデル絞り込み(こちらは DB 内のモデル名を使う別物で、触らない)。

## アンチゴール(技術的には動いても失敗とみなすもの)

- ネットワーク断や取得元の不調で、ビルドが止まる。
- 実在しない ID や、正式な ID と書き方が違う ID が、選択肢に混ざる。
- 埋め込み用や、テキストを出力できない(画像だけ・音声だけを出力する)モデルなど、補完のプロンプトを送っても動かないモデルが、選択肢に混ざる。
- 人の確認なしに、勝手にコミットされる。

## 制約

- shinasadame は FastAPI + Jinja2 + htmx で、フロントは素の JavaScript(`static/app.js`)。JS のビルド工程は無い。
  依存の追加は避ける。
- Python は 3.11 以上、パッケージ管理は `uv`。
- モデルの指定形式は `provider/model`(`google/`・`anthropic/`・`openai/`・`xai/`)。replay が解釈する。
- 取得元(2026-10-17 時点の調査)
  - OpenRouter 公開 API `https://openrouter.ai/api/v1/models`: キー不要・全社分(469 件)・`created`(作成日)付き。
    ただし ID の書き方が各社の正式な ID と違うことがある(`anthropic/claude-haiku-5.5` と `claude-haiku-5-5`)。
    `:batch` 付きの重複も含まれる。
  - LiteLLM の公開 JSON(`https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json`):
    キー不要・各社の正式な ID・日付なし。
  - 各社の公式ページは使わない。OpenAI のページはカード表示で一部しか取れず、ID も推測になるため。
- イメージのビルドは、`shinasadame/Dockerfile` が `src` を COPY する。一覧ファイルは `src` の中に置けばイメージに入る。
- Skaffold は `skaffold.yaml` の `build.artifacts[]` にフックを書ける。
- 既存のテストは pytest(`shinasadame/tests`)。ネットワークに依存するテストは書かない。

## 決めたこと(あなたの判断)

1. 対象は「各社」で、キーの有無を問わない。範囲は、取得時点で使える全モデル(新旧とも)。廃止済みは含めない。
2. 保存はリポジトリにコミットするファイル。
3. 自動で回すタイミングはビルド時。
4. 画面は複数段のメニュー(会社 ▸ 系列 ▸ モデル)。

## 私の判断(あなたが決めたことではない。違えば直す)

- **取得元**: 主に OpenRouter。LiteLLM で、正式な ID への正規化と、その ID が実在することの確認をする。
  LiteLLM に正規化先が見つからないモデルは、一覧に入れない(実在しない ID を混ぜないため)。
- **「使える」の定義**: OpenRouter の一覧に載っているものを「その時点で使える」とみなす。
- **テキストを出力できるモデルに絞る**: OpenRouter の出力モダリティに text を含むかで判定する(項目名は実物で確認すること)。
  マルチモーダルなモデル(画像や音声も入力・出力できるもの)も、テキストを出力できれば通す。
- **失敗時**: 取得か整形に失敗したら、既存のファイルを残して警告を出し、ビルドは続ける。
  成功しても件数が極端に減った場合(例: 半分未満)は、壊れたとみなして上書きしない。
- **保存形式と場所**: スクリプトは `shinasadame/tools/update_models.py`(Python 標準ライブラリだけ)。
  結果は `shinasadame/src/shinasadame/models.json`(イメージに入る)。
- **`SHINASADAME_MODELS` の扱い**: 設定されていれば、それを従来どおり優先する(明示的な上書き)。設定が無ければ JSON を使う。
  `deployment.yaml` の既存の値は、削除する。
- **系列の切り出し**: モデル名から機械的に切る(例: `gpt-6.1-sol` → 系列 `gpt-6.1`)。会社ごとに数字の付き方が違うので、
  切り出し方は会社ごとのルールにする。切り出せないモデルは、会社の直下に並べる。
- **並び順**: 会社は固定順、系列とモデルは新しい順(`created` 降順)。
- **既存の挙動は維持**: 記録のモデルから作る既定値(`default_model`)は、引き続き先頭で選択済みにする。
  「一覧にないモデル」の自由入力(`model_custom`)も残す。
- **スキップするか**: キーを持たない会社のモデルを選ぶと、実行時に認証エラーになる。これは許容する
  (選べることが目的)。画面で明示するかどうかは、ビルダーに任せる。
- **コミット**: 一覧ファイルの更新はコミットしない。あなたの指示があったときだけコミットする。

## 細部の判断(私の判断。設計書の確認で出た疑問への答え)

- **ID の突き合わせ**: OpenRouter の ID を会社ごとのルールで正式な形に直し(例: Anthropic は `.` を `-` に、
  `x-ai/` は `xai/` に、`:batch` 付きは除く)、LiteLLM のキーと**完全一致**したものだけを採用する。曖昧な一致はしない。
  会社ごとにルールで直せないものは、スクリプト内の小さな対応表(手で保守する)で補う。
  Gemini の `gemini-4-argon` のように、両者で綴りが食い違う場合も、この対応表で直す。
- **日付付きの版と別名**: 日付付きの版(例: `claude-sonnet-4-5-20250929`)は、日付なしの同じモデルがあれば載せない。
  `-latest` の別名は、呼び出せる ID なので載せる。
- **OpenRouter に無く LiteLLM にだけある**モデルは、載せない(「使える」の基準は OpenRouter)。
- **採用の判定**: OpenRouter の出力モダリティに text を含み、入力にも text を含むこと(**あなたの指示**: text だけでなく、
  text を出せるマルチモーダルなモデルも通す)。さらに LiteLLM の `mode` が `chat` であること。
  テキストを出力できない(画像だけ・音声だけを出す)モデルと、埋め込み用は除く。
  画像も出せるモデルが LiteLLM の `mode` で `chat` 以外に分類されて落ちる場合は、`mode` の条件を緩める(ビルダーが実データで確認する)。
- **系列は表示用**: 保存される値は今までどおり `provider/model` で、フォームも単一の `model` フィールドのまま
  (バックエンドは変えない)。系列は初版では会社ごとに次のように切り、メニューを見てから直す。
  Anthropic は家族名(haiku / sonnet / opus / fable)、Google は `gemini-N.M`、OpenAI は `gpt-N(.M)`、xAI は `grok-N(.M)`。
- **記録のモデル(`default_model`)が一覧に無いとき**: 一覧に無くても、メニューの先頭に選択済みの項目として出す。
- **フックの範囲と失敗時の扱い**: フックは shinasadame のイメージ(`web` 側)のビルド前だけ。`uv` や Python が無い場合も、
  警告だけでビルドは続ける。「件数が半分未満」の判定は、既存ファイルの件数が基準。
- **初回**: 初回に取得に失敗しても空の一覧を配らないよう、最初の `models.json` は、あなたがコミットする(種になるファイル)。
- **`models.json` が無い・空のとき**: 画面はエラーにせず、自由入力欄だけで使える。
- **`SHINASADAME_MODELS` を設定したとき**: 同じ複数段メニューの中に、会社ごとにまとめて並べる(平らな一覧にはしない)。
  既存のテスト(`test_trial.py`、`test_replay_client.py`)は、この環境変数を前提にしているので、通り続けること。

## ビルダーに任せること

- スクリプトの内部構成、ファイル分割、関数の切り方。
- 件数の少ない系列(1〜2 件)のメニュー上の見せ方。
- 複数段のメニューの実装方法(`details` を入れ子にする、独自の CSS メニューなど。キーボード操作と、
  メニューが画面外にはみ出さないことは必要)。
- 一覧ファイルの JSON の細かい構造(会社・系列・モデルの入れ子など)。
- テストの書き方(取得結果のサンプルを固定して整形処理だけをテストする、など)。
- Skaffold のフックの書き方(失敗しても止めない指定を含む)。

## 完了の確認

- `uv run python tools/update_models.py` で `models.json` が更新される。ネットワークを切った状態で実行すると、
  警告が出て既存のファイルが残り、終了コードは成功のまま(ビルドが止まらない)。
- 一覧には、4 社それぞれの最新モデル(調査時点: `gemini-4-argon`、`claude-haiku-5-5`、`gpt-6.1-sol`、`grok-4.7`)が入り、
  埋め込み用や、テキストを出力できないモデルは入らない(テキストを出せるマルチモーダルなモデルは入る)。
- 「試す」パネルで、会社 ▸ 系列 ▸ モデルと開き、選んだモデルで実行できる(キーのある Gemini で実行まで確認する)。
- `skaffold run -p web` で、ビルド前にスクリプトが走る。
