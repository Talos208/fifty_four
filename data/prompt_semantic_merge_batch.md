複数のキャラクター設定について、属性セクションごとに「現在の設定」と「新しく本文から読み取れた情報」を、意味が自然につながるようにマージせよ。

# マージ規則（全セクション共通）
- `merged_text` はマージ後の属性セクション本文のみとする。見出し、説明、コードフェンスは含めない。
- 行頭に属性名のラベル（「口調：」「呼称：」等）を付けない。見出しで既に示されているため不要。
- 「マージ後の文章：」のような、これから本文を書くことを説明する前置きも一切付けない。1行目からいきなり本文を書き始めること。
  - 悪い例: 「マージ後の文章：
落ち着いた性格。」
  - 良い例: 「落ち着いた性格。」
- 現在の設定をベースにし、消えていない既存情報は保持する。
- 既存情報に重複があるなら、新情報について処理する前にマージする。
- 新情報が既存情報と同じ意味なら重複させず、より自然な一文に統合する。
- 新情報が既存情報と矛盾・更新関係にある場合は、両方を機械的に並べず、矛盾しない表現へ合成する。必要なら「以前は」「現在は」「普段は」「状況によって」などの限定を使う。
- 本文から読み取れない内容を推測で追加しない。
- 既存が Markdown 箇条書きスタイルなら、できるだけ維持する。
- 呼称とセリフ例を除き、箇条書きは使わない。説明する文章として読みやすいよう、適切に改行も含めること
- nameが他のキャラクターのaliasesに含まれる場合、同一のキャラクターとして扱う。
  - ただし、nameが一般名詞、呼称、立場、職業、よくある名前など複数名存在する可能性が高い場合、他のaliasesや属性などから同一キャラクターかどうか慎重に判断する。
- 同じキャラクターの同じ属性が複数ある場合は、現在の設定同士、新しい情報同士でもマージする

# 結果の返し方
- 与えられた全てのキャラクター・全てのセクションについて、必ず結果を返すこと。1件も省略してはならない。
- `name` と `heading` には、与えられた「キャラクター:」「セクション:」の文字列を一字一句そのまま返すこと（復唱）。言い換え・省略・敬称の付加をしない。
